# «Мой ритм» — фронтенд

**Живой сайт:** https://npopko55-cmd.github.io/moy-ritm/

Три экрана из макета: лендинг, обратный отсчёт и плеер тренировки.
React 18 + TypeScript + Vite, без UI-библиотек. Вся палитра и размеры —
в одном файле `src/styles/tokens.css`.

## Запуск

```bash
npm install
npm run dev
```

Откроется `http://localhost:3000`. Если порт занят, задайте свой:
`PORT=3100 npm run dev`.

Сборка: `npm run build`, результат в `dist/`.

## Экраны

| Адрес                | Экран                                                    |
|----------------------|----------------------------------------------------------|
| `/`                  | Лендинг                                                   |
| `/start/:streamId`   | Отсчёт 3-2-1, затем сам уводит в плеер                    |
| `/player/:streamId`  | Плеер: персонаж, таймеры, переключение потоков            |

`streamId` — один из `cardio`, `back`, `office`, `dance`, `60plus`.

## Ролики с движениями

В `public/loops/` лежат 14 зацикленных роликов **с прозрачным фоном** —
персонаж вырезан по контуру, поэтому в круге нет бежевой подложки.
Каждый ролик в двух форматах:

- `<id>.webm` — VP9 с альфа-каналом (Chrome, Firefox, Edge);
- `<id>.mp4` — HEVC с альфа-каналом (Safari, который альфу в WebM не умеет).

Нужный вариант выбирается в `src/data/loops.ts` по браузеру.

### Как пересобрать ролики из исходников

```bash
bash scripts/build-loops.sh "/путь/к/ЛУПЫ ГОТОВЫЕ/Один цикл"
```

Что делает скрипт: разбирает исходный mp4 на кадры, вырезает человека
через системный фреймворк Apple Vision (`scripts/cutout`, сборка из
`scripts/cutout.swift`), обрезает кадр по общему контуру всех кадров,
масштабирует до 720×720 и кодирует оба формата.

Пересобрать сам инструмент вырезки, если нужно:

```bash
swiftc -O scripts/cutout.swift -o scripts/cutout
```

Требуется macOS с ffmpeg (`brew install ffmpeg`) и Command Line Tools.

### Добавить новое движение

1. Положите исходный mp4 в папку с лупами.
2. Добавьте строку в `slug_for()` в `scripts/build-loops.sh`.
3. Перезапустите скрипт.
4. Впишите ролик в `LOOPS` в `src/data/loops.ts` (id, название, длительность цикла).
5. Добавьте id в нужные потоки в `src/data/streams.ts`.

## Что сейчас на моковых данных

Экран собран так, чтобы данные подменялись в одном месте, без правок вёрстки:

- **`src/data/streams.ts`** — потоки, их id совпадают с `app/seed.py` бэкенда,
  фразы мотивации те же, что отдаёт `GET /api/v1/motivation`.
- **`src/data/loops.ts`** — `SECONDS_PER_MOVE = 30`: сколько крутится одно
  движение до смены.
- **Плеер** стартует со значения 12:47 в карточке «Время в движении сегодня»
  и дальше считает сам. Под API это место меняется на `GET /api/v1/activity/stats`.
- **Недельный график** в карточке «Сегодня» — статические данные, массив `WEEK`
  в `src/screens/Player.tsx`.

Отправку активности (`POST /api/v1/activity/sync`) специально не подключал:
у бэкенда сейчас есть блокирующие проблемы из ревью, их надо закрыть первыми.

## Деплой

Сайт публикуется на GitHub Pages автоматически: любой push в `main` запускает
`.github/workflows/deploy.yml`, который собирает проект и выкладывает `dist/`.

Две особенности подпапки `/moy-ritm/`, о которых стоит помнить при правках:

- пути к файлам из `public/` идут через `asset()` из `src/lib/asset.ts`,
  абсолютный `/loops/x.webm` на Pages ведёт в никуда;
- прямые ссылки вида `/player/cardio` работают за счёт копии `index.html`
  под именем `404.html` — её создаёт шаг в workflow.

Сменить адрес: поправить `base` в `vite.config.ts` под новое имя репозитория.
